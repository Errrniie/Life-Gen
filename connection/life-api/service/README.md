# Service architecture and setup

## Runtime

`main.py` creates the FastAPI application, loads `.env` through `python-dotenv`, and requires `API_KEY` at process startup. `GET /health` is public; the other routers attach `verify_api_key`, which checks the `x-api-key` header. The app calls `ensure_schema()` on startup. Running `main.py` directly starts Uvicorn on `0.0.0.0:8000`; the README's development command is `uvicorn main:app --reload`.

## Request and persistence path

```text
HTTP request → FastAPI router → Pydantic input/output model
             → db.get_conn() → PostgreSQL (psycopg)
```

Routers contain endpoint SQL and transaction handling. `db.py` opens a psycopg connection from environment variables and `ensure_schema()` creates tables, indexes, constraints, seed journal page types, and compatibility alterations. JSON fields are stored as PostgreSQL `JSONB`. UUIDs are generated by PostgreSQL using `pgcrypto`.

## Configuration

Required environment variables: `API_KEY`, `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`. `PGPORT` defaults to `5432`; `PGSSLMODE` defaults to `require`. `requirements.txt` pins FastAPI, Uvicorn, psycopg, Pydantic, and python-dotenv. The Dockerfile uses Python 3.12 slim, installs the requirements, copies the service into `/app`, and starts Uvicorn on port 8000.

## Source map

- `main.py`: app creation, startup schema call, health endpoint, router registration.
- `dependencies.py`: API-key dependency.
- `db.py`: PostgreSQL connection and schema setup.
- `routers/`: route handlers and SQL, grouped by resource.
- `models/`: Pydantic request/response models.
- `API.md`: route contract; `life_engine_database_table_reference.md`: schema reference.

## Data and deletion

The database has `sessions`, `activities`, `records`, `tasks`, `journal_entries`, `journal_pages`, and `journal_page_types`. Most resources use soft-delete columns (`deleted_at`, `deleted_reason`) and list routes normally omit deleted rows. Foreign keys also specify physical `ON DELETE CASCADE`; normal API deletes are soft deletes and implement their own selective cascade behavior. See the database reference for details.
